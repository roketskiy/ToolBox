# ToolBox 设计规格

- 日期：2026-08-07
- 状态：已确认
- 目标平台：Windows 10/11

## 1. 背景与目标

用户拥有多个体积小、使用频率低的本地工具，例如图片批量压缩和字幕提取程序。由于工具分散且长期不用，用户容易忘记工具用途或可执行文件位置。

ToolBox 是一个带简介的本地程序目录。它只负责记录、搜索和启动现有工具，不重新实现工具功能，也不管理工具的下载、安装或升级。

第一版成功标准：

1. 用户选择一个 `.exe` 后，名称、路径、工作目录和图标能自动补全。
2. 正常情况下，用户只需填写简介即可完成添加。
3. 工具以小卡片显示，可通过名称或简介即时搜索。
4. 单击卡片能使用保存的工作目录和启动参数运行程序。
5. 程序重启后数据仍然存在；路径失效或程序启动失败时不会崩溃。

## 2. 范围

第一版包含：

- 顶部搜索框
- 响应式工具卡片列表
- 右下角圆形添加按钮
- 添加、编辑和移除工具记录
- 从 EXE 自动读取名称和图标
- 保存程序路径、工作目录和启动参数
- 单击卡片启动程序
- 路径失效提示和重新定位
- 本地 JSON 持久化

第一版明确不包含：

- 分类、标签、收藏和运行历史
- 托盘常驻和全局快捷键
- 插件系统、在线商店和自动更新
- 自动扫描磁盘或开始菜单
- 内置图片压缩、字幕提取等工具逻辑
- 云同步、多用户和权限管理
- 数据库、WebView 或跨平台支持
- 深色模式和主题系统

## 3. 技术选择

采用 C#、WPF 和 .NET 10 LTS，目标为 Windows x64。

运行时不引入第三方 UI 框架、MVVM 框架、依赖注入容器或数据库。使用 WPF 和 .NET 标准能力完成窗口、JSON、文件信息读取和进程启动。

选择 WPF 的原因：

- Windows 原生集成直接，适合读取 EXE 元数据和关联图标。
- 不需要 Electron、WebView 或 Rust/前端双技术栈。
- 自定义窗口外观、文件拖放和进程启动均有成熟系统 API。
- 代码和运行时依赖可以保持在本项目实际需求内。

默认发布依赖系统安装的 .NET Desktop Runtime，以减少发布体积。需要拷贝即用时，可以额外生成自包含版本，但不作为第一版唯一发布方式。

## 4. 数据模型与存储

每个工具只保存以下字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | GUID | 内部稳定标识 |
| `name` | string | 工具显示名称 |
| `description` | string | 用户填写的简短用途说明 |
| `executablePath` | string | EXE 绝对路径 |
| `workingDirectory` | string | 启动时工作目录 |
| `arguments` | string | 原样传递给目标程序的启动参数 |
| `iconPath` | string/null | 可选自定义图标路径；为空时从 EXE 提取 |

工具记录按 JSON 数组顺序显示和保存。数据文件位于：

```text
%LOCALAPPDATA%\ToolBox\tools.json
```

保存时先写入临时文件，再原子替换正式文件，并在同一目录保留 `tools.json.bak` 作为最近的有效备份。JSON 解析失败时不覆盖原文件；如果备份有效则从备份读取，否则显示错误并保持空列表。

图标不以二进制形式写入 JSON。自动图标在运行时从 EXE 提取并在内存中缓存；只有用户选择自定义图标时才保存图标路径。

## 5. EXE 自动补全

点击添加按钮后打开 Windows 文件选择器，仅允许选择 `.exe`。

选择完成后按以下顺序补全字段：

1. `name`：优先使用 `FileVersionInfo.ProductName`。
2. 如果为空，使用 `FileVersionInfo.FileDescription`。
3. 如果仍为空，使用不带扩展名的文件名。
4. `executablePath`：所选文件的规范化绝对路径。
5. `workingDirectory`：EXE 所在目录。
6. `arguments`：空字符串。
7. `iconPath`：空值，界面直接读取 EXE 关联图标。
8. `description`：空字符串，等待用户填写。

随后显示紧凑编辑窗口。所有字段均可修改，但自动补全后的正常流程只需要填写简介并保存。

名称、简介和有效 EXE 路径为必填项；工作目录、启动参数和自定义图标为可选项。保存前去除名称和简介首尾空白。

如果同一路径已经存在，按照 Windows 不区分大小写的路径规则识别重复项，不创建重复记录，而是打开已有记录的编辑窗口。

## 6. 主界面

主窗口默认尺寸为 920 x 640，最小尺寸为 680 x 480。

界面由三个区域组成：

1. 自定义标题栏：左侧为关闭、最小化和最大化圆点，保留标准窗口快捷键和双击标题栏最大化行为。
2. 顶部搜索区：一个固定高度的搜索框，包含搜索图标和清除按钮。
3. 工具区：搜索框下方为可滚动、自动换列的卡片网格。

右下角固定一个 48 x 48 的圆形添加按钮，内部使用加号图标。列表滚动时按钮位置不变。

卡片建议尺寸为 240 x 104，圆角不超过 8px。卡片包含：

- 48 x 48 程序图标
- 单行名称，超长时省略
- 最多两行简介，超长时省略
- 悬停或键盘聚焦时出现的更多操作图标

单击卡片主体或在卡片聚焦时按 Enter 直接启动工具。更多操作菜单包含：

- 编辑
- 打开程序所在目录
- 从 ToolBox 移除

“移除”只删除目录记录，绝不删除磁盘上的 EXE。移除前需要确认。

工具为空时显示简短空状态和添加按钮，不展示教学说明或功能介绍。

## 7. 搜索行为

搜索只匹配 `name` 和 `description`，使用不区分大小写的包含匹配。输入变化后立即过滤，不使用模糊搜索库、拼音索引或全文索引。

搜索内容为空时恢复全部工具，并保持 JSON 中的原始顺序。

## 8. 启动行为

启动前检查 `executablePath` 是否存在：

- 存在：通过 `ProcessStartInfo` 启动，分别设置 EXE、工作目录和参数，不拼接 Shell 命令。
- 工作目录为空或不存在：回退到 EXE 所在目录。
- EXE 不存在：不启动，显示“程序路径已失效”，提供重新定位和取消操作。
- 启动抛出异常：显示简短错误信息，应用继续运行。

第一版不提供管理员身份启动，也不执行下载自网络的命令。

## 9. 视觉规范

界面采用 macOS 启发的浅色视觉，但保持 Windows 的可访问性和窗口行为。

- 页面背景：`#F5F5F7`
- 卡片背景：`#FFFFFF`
- 主文字：`#1D1D1F`
- 次文字：`#6E6E73`
- 边框：`#D2D2D7`
- 强调色：`#007AFF`
- 字体：`Segoe UI Variable`，缺失时回退到 `Segoe UI`
- 卡片圆角：8px
- 搜索框圆角：8px
- 动画时长：120 至 160ms

窗口控制圆点使用红、黄、绿三色，并提供工具提示和键盘等价操作。搜索清除按钮、卡片操作按钮和添加按钮均设置可访问名称及工具提示。界面不使用渐变、背景模糊、透明玻璃、大面积阴影或装饰图形。轻微阴影仅用于区分卡片和背景。

## 10. 错误处理

- EXE 元数据读取失败：回退到文件名。
- 图标提取失败：显示内置通用程序图标。
- JSON 不存在：创建空列表，不视为错误。
- JSON 损坏：保留原文件，尝试有效备份，并提示用户。
- 数据保存失败：保留内存中的当前列表并提示，不假装保存成功。
- 自定义图标失效：回退到 EXE 图标。
- 程序路径失效：卡片仍保留，启动时提供重新定位。

所有错误提示均应包含可执行的下一步，不展示堆栈信息。

## 11. 验证

自动检查聚焦于最容易导致数据损坏或行为回归的逻辑：

- JSON 保存和读取往返后字段保持一致。
- 名称补全按 ProductName、FileDescription、文件名的顺序回退。
- 搜索对名称和简介执行不区分大小写的包含匹配。
- 同一路径不会创建重复记录。

发布前执行桌面冒烟检查：

1. 添加一个带版本信息和图标的 EXE，只填写简介后保存。
2. 关闭并重启 ToolBox，确认卡片仍存在且图标正常。
3. 分别通过名称和简介搜索该工具。
4. 设置工作目录和参数，确认目标程序收到正确配置。
5. 移动 EXE，确认路径失效提示和重新定位可用。
6. 编辑记录后确认内容更新。
7. 移除记录，确认 EXE 文件仍然存在。
8. 在 680 x 480 和 920 x 640 窗口尺寸下检查搜索框、卡片和添加按钮没有重叠或溢出。

## 12. 后续边界

只有真实使用证明有需要时，才考虑托盘快捷启动、全局热键、便携数据目录或参数占位符。第一版不为这些能力预留插件接口或抽象层。
